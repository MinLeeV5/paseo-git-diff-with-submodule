Review local Git changes across a workspace and its initialized nested submodules, including submodules configured with `ignore = all`. Each repository is compared against its own HEAD. You can review all uncommitted changes, staged changes, or unstaged changes while keeping standard Git ignore rules.

The workspace panel provides a compact file list or tree, file type icons, language-aware syntax colors, and scrollable tabs for multiple files. Compare changes side by side or in a unified view. Resize the file sidebar and comparison split, filter file paths, jump between change blocks, and adjust whitespace, context, line numbers, and wrapping.

Use the left icon dropdown to switch between Changes and the GitLens-inspired commit graph. Browse colored branch and merge lanes, HEAD, local and remote branches, and tags for the root repository or any initialized submodule. Filter by ref, load history in pages of 100, or search loaded messages, authors, emails, and SHAs without losing the graph topology. Enter and Shift+Enter move between search matches while keeping the input focused. Select a commit to inspect its message, parents, and changed files, then open a historical side-by-side or unified diff. Drag the details panel's top edge to resize it; its height ratio is saved on the host. Merge commits compare with their first parent; root commits compare with the empty tree. Narrow panels use a separate details page. Switching views preserves their tabs, selection, and scroll areas. History refreshes manually and reads local Git objects without fetching.

Markdown, HTML, and images support full-file previews. Markdown includes offline Mermaid diagrams. HTML previews do not run scripts, and document previews block external and relative image resources. Markdown links open workspace files, including unchanged files and files in submodules, in reusable tabs with heading anchors. Code links open a read-only syntax-colored view; web links use the client’s external browser. Local links are confined to the workspace. Rich document previews are available on desktop and Web; native mobile clients fall back to text. Sidebar and tab context menus copy absolute or workspace-relative paths; tabs also support closing the current tab, others, either side, or all tabs. The file context menu reveals a file in Finder or the file manager on the daemon host, or its nearest existing parent if the file was deleted.

Settings are grouped into Appearance, Code, Comparison, and Behavior. Fonts, weight, size, and other display preferences are saved on the current Paseo host. Git status refreshes every two seconds by default, with configurable intervals and a pause control; polling stops in the background. Existing tabs remain local to the panel session.

Requires Paseo daemon and client 0.12.0 or later, and Git on the daemon host. Git commands and file reads run on that host; the client receives status, diffs, and previews through Paseo RPC. The plugin does not transmit repository contents to external services or read service credentials. Preview rendering and icons use bundled assets.

This is a read-only review tool. It does not stage, discard, commit, push, switch branches, or initialize submodules. Comparisons between arbitrary refs are not provided. Working and historical files and previews are limited to 1 MiB, and patches to 2 MiB; larger or binary entries retain their status and explain the reading limit. Missing parents at shallow clone boundaries are reported explicitly.

The last five visited tabs retain their mounted contents and scroll positions by default. Configure 1–10 in Settings → Behavior. Older panes are evicted earlier under an estimated 24 MiB content budget; the active pane remains available. This is not a browser heap limit. Unchanged cached tabs do not reload; changed files and comparison options invalidate their contents. Closing the panel releases content caches. Legacy patch-layout preferences migrate to unified view.

The Settings footer always shows the plugin version, generated from the package release metadata.
