# GitLens 性能优化与回归验证

性能对测冻结源码 SHA-256：`fc953420280087212f4a628b24ed2446bf81e0ca6e1b586aa167e7686466ec50`。基线为 v0.6.0 提交 `c39dcdfc80994b9672701059c1e5878ddf2f67a3`，其 server/shared 与开始优化前的提交 b0611d6 相同。本轮未变更版本号。

本轮已实现按仓缓存、定向失效、有界并行、逐仓展示、刷新保留旧 diff、交互优先、精简传输，以及受条件约束的补丁合并。最终 196 个正式样本、7 类场景的 77 项门槛通过。耗时数据是服务端与 RPC 数据就绪时间，不是浏览器绘制时间。

## 不退化门槛

- 固定旧版和候选源码，装进同一个官方 0.16.0-beta.1 隔离 daemon；真实 loopback WebSocket，交替旧版/新版的执行顺序。建库、复制、启动、预热、间隔等待不计时。
- 各场景至少 7 轮；对波动项和压力场景另启隔离 daemon，追加 21 轮。相同源码的所有正式样本均纳入，N 见表。合计 196 个正式样本，16 个不计入统计的预热样本。
- 中位数增加超过 5 ms 即要求复测；亚毫秒热缓存使用 0.5 ms；payload 不允许增加。回归脚本默认在出现标记时退出 1，合并检查包含所有同源码正式样本。
- 不隐藏中位数小幅增加的指标，也不丢弃慢样本。下列数值在预设门槛以内；全部样本、极值与宿主负载保存在原始 JSON 中。

小幅增加项（单位 ms）：

- 1000 个已跟踪文件，`cachedFileMs`：0.179 → 0.188，增加 0.009；门槛 0.5。
- 10 仓库 / 200 个文件，`cachedFileMs`：0.187 → 0.276，增加 0.089；门槛 0.5。
- 500 个已跟踪文件，`cachedFileMs`：0.194 → 0.197，增加 0.003；门槛 0.5。
- 500 修改 + 500 未跟踪，`cachedFileMs`：0.196 → 0.200，增加 0.004；门槛 0.5。

这是本机、固定工作量与协议路径的验收，不是所有机器、仓库、网络和长期 P95 的无条件保证。没有测移动设备、网络 RTT、浏览器 FPS 或独立的 RSS/CPU 上限。本轮一分钟宿主 load 范围为 2.03–7.13，未做系统级 CPU/磁盘隔离；因此保留全部波动并对标记项复测。

## 实现与边界

- 仓库体缓存维持 1000 ms TTL，强制刷新使用单调代次；按需只读取目标仓库及其祖先，Git 操作只失效目标及祖先，保留兄弟仓库补丁。缓存有条目和估算字节预算，只保留变更文件的基线对象。
- 最多并行读取 3 个仓库，Git 进程总预算仍为 6；冷启动先返回已就绪仓库，最终保持原有 DFS 顺序。刷新已有完整树时保留旧树，新的完整树就绪后替换。
- 交互请求复用并提升正在进行的相关读取，不重复根仓定位；队列按优先级取下一任务，失效和卸载取消相关元数据与补丁的排队/在途 Git 读取。
- 新增增量仓库视图与精简补丁视图 RPC；保留原 RPC。无变化的轮询不传仓库文件数组，客户端保留未变化仓库的对象。
- 文本 diff 刷新期间保留旧内容、滚动与差异导航；失败显示重试提示并保留旧内容，切换文件不显示另一文件的内容。
- 补丁合并只面向同仓、同 HEAD、同设置、同基线对象的已请求普通 tracked 文件。首个请求立即执行；确认标准补丁头后才允许短窗口合并，最多 32 项、等待最多 2 ms。基线和当前文件均不超过 64 KiB 才合并，保留原有 1 MiB 文件 / 2 MiB 单补丁限制及回退路径。不同基线对象、特殊名称、未跟踪文件、暂存/未暂存比较均走原读取；没有全量预取或常驻子进程。

性能门槛曾拒绝两类实现：后台读取重复定位根仓；为不同基线对象反复查询大小。仅把 `ls-tree` 换成批量 `cat-file` 仍不能消除后者，所以最终明确按基线对象分组，让不同内容的文件直接走原路径。相关中间版本的全部数据单独归档，未混入最终统计。

常驻文件 watcher 暂未引入；继续使用可配置轮询、后台暂停与失败退避，避免未经本轮验证的跨平台观察开销。
